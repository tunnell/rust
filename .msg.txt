std: xous: carry the nonblocking flag on TCP send requests

set_nonblocking is client-side state that is encoded onto the rx, peek,
and accept requests as opcode bit 15, but StdTcpTx never carried it, so
the net server cannot tell a nonblocking write from a blocking one: once
the send buffer is full it parks the request in tcp_tx_waiting with no
expiry, and a nonblocking write hangs indefinitely instead of failing
with WouldBlock.

Add the nonblocking bool to NetLendMut::StdTcpTx, mirroring the existing
StdTcpPeek and StdTcpRx arms, and pass the socket's nonblocking state in
TcpStream::write. The reply decode already maps the server's WouldBlock
code, so no decode changes are needed. A server that predates the tx-
side flag masks bit 15 off the opcode and behaves exactly as today, so
the change is inert until both sides ship.

Validated under Renode by the net-tests suite:
errors::tcp_nonblocking_write_wouldblock flips from expected-failure to
pass on images pairing this client with a net server that honors the
flag on the tx path.
